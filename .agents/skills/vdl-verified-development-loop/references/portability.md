# Portability

Install the complete skill from a published GitHub repository with `npx skills add LongIch2810/verified-development-loop --skill vdl-verified-development-loop --copy -y`; add `-g` for a global skill. The CLI detects installed agents. The VDL installer keeps the shared package at `.agents/skills/vdl-verified-development-loop/` and does not create a `.claude/skills/` entry. Its `SKILL.md`, shared role definitions in `agents/`, templates in `assets/templates/`, and scripts are the whole workflow package. Any host that can read skills, run Python commands, and launch native subagents can use the same role instructions. The main agent supplies each role file's contents in the delegation prompt; no host-specific agent configuration is required for workflow state or phase events. Model choice follows the host and user settings, so report the actual model only when the host exposes it.

Run `python .agents/skills/vdl-verified-development-loop/scripts/install_vdl.py --target .` after installing the skill (`python3` on macOS/Linux), or run both in a single command (`npx skills add LongIch2810/verified-development-loop --skill vdl-verified-development-loop --copy -y; python .agents/skills/vdl-verified-development-loop/scripts/install_vdl.py --target .` on PowerShell, or `&&` on CMD / macOS / Linux). `npx skills add` alone does not execute installation scripts. The script initializes `.verified-development-loop/{specs,plans,tasks,errors,evidence,reports}`, registers Codex, Claude Code, Cursor, and Antigravity lifecycle hooks on Windows, macOS, and Linux, and starts the Control Center at `http://127.0.0.1:4040`; `--no-control-center` skips the dashboard. Reinstalling reuses a Control Center already serving the same project. Port 4040 must be available for that project. Use `--no-hooks` to skip registration, or combine it with `--codex-hooks`, `--claude-hooks`, `--cursor-hooks`, or `--antigravity-hooks` to select hosts. Windows hooks use the bundled `.cmd` launcher; macOS/Linux hooks call `python3` directly. Without a hook, the dashboard sees only explicit `workflow.py emit` and state-gate events; it cannot passively observe chat or subagent activity. Other hosts need their own adapter for passive observation. Reinstalling removes only `.claude/skills/` entries previously generated by this installer; user-written entries remain. The separate `npx skills add` command may place skills according to its own selected agents. No host-specific role definitions are created, and project instructions are preserved. Python 3.11+ and Git are required. Define real verification commands for each repository during planning.

The workflow script stores all task records as `.md` files under `.verified-development-loop/`: Specs and Plans use `drafts`, `active`, and `completed`; Tasks use `active` and `completed`; errors, evidence, and human reports have their own directories. `.vdl/` remains an ignored dashboard event cache.

The scripts gate only transitions made through them. Human approval, reviewer independence, acceptance judgment, and adherence to scope require agent and human discipline. The main agent runs `workflow.py emit` around native subagent delegation on every host, so children need no hook or shell access. Host hooks add generic lifecycle events only; they do not identify workflow roles. See [real-time tracking](tracking.md) for the common event commands.
