# Evidence contract

Each verification record in `.verified-development-loop/evidence/TASK/` is Markdown (`.md`) with readable evidence and embedded machine state. It contains time, source fingerprint, PASS/FAIL, and every approved command's argv, exit code, stdout, and stderr or execution error. The coder's [TDD handoff report](../agents/tdd-coder.md) and the reviewer's [code review report](../agents/code-reviewer.md) are separate Markdown handoffs in the same Task evidence directory; the main agent checks and retains their paths. CLI review records contain reviewer name, PASS/FAIL, findings, matching fingerprint, and linked verification record. QA records contain tester name, PASS/FAIL, matching fingerprint, the full [QA report](../assets/templates/template-qa-report.md), and links to the current verification and review. The QA report records the full suite, every approved scenario, actual commands or actions and outputs, additional edge cases, and limits; a conclusion without actual evidence is not PASS. Acceptance records link verification, review, and QA and enumerate the criteria attested by the main agent.

The fingerprint hashes Git HEAD and the contents of tracked and nonignored untracked project files, excluding workflow metadata (`specs`, `plans`, `tasks`, `errors`, `evidence`, the skill, agent TOMLs, and `AGENTS.md`). A code change invalidates old PASS evidence. Ignored/generated files are outside this fingerprint; include any such build outputs in the project's verification commands if relevant.

Use repository-specific lint, typecheck, unit/integration tests, build, and domain/security checks where applicable. Store the real command and output. Do not substitute a prior run or a fake test. Report commands that were unavailable or not run as UNVERIFIED. The CLI checks state consistency, not reviewer or QA independence, truth of reported observations or acceptance attestation, or authenticity of human approval.
